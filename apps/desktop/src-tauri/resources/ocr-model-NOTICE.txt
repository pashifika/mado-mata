Storage and cancellation
  The application never overwrites published installations or mutates manual
  resource paths. Same-filesystem staging is published by directory rename only
  after exact hashes, license texts and a receipt are complete. A persistent
  OS-backed exclusive file lock prevents another setup process from reclaiming
  active staging. Interrupted known staging is reclaimed only on explicit setup,
  never on GUI startup. Unknown files and links are retained with cleanup errors.
  Cancellation is checked between bounded reads and immediately before rename.
  A stalled network read can wait up to the 120-second request timeout; individual
  operating-system filesystem calls do not have a physical completion deadline.
  After publication, late cancellation does not remove the completed installation.
